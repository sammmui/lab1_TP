## Використання CLI (`cli.py`)

Інтерфейс командного рядка забезпечує взаємодію з ядром мови та підтримує структурований JSON-вивід (`--json`) для інтеграції з IDE та іншими інструментами (вимога **CORE-05**).

### Формат команди
```bash
python cli.py <command> <file_path> [--json]
```

### Команди

| Команда | Призначення | Приклад запуску |
| :--- | :--- | :--- |
| **`check`** | Перевіряє лексичну та синтаксичну коректність файлу SIPL. | `python cli.py check tests/positive/test01.sipl` |
| **`parse`** | Будує та виводить типізоване AST із координатами `SourceSpan`. | `python cli.py parse tests/positive/test01.sipl --json` |
| **`run`** | Виконує програму та повертає фінальний стан пам'яті (змінних). | `python cli.py run tests/positive/test04sipl` |
| **`trace`** | Виконує програму та формує JSON-трасу подій виконання. | `python cli.py trace tests/positive/test04sipl` |

### Коди завершення (Exit Codes)
* **`0`** — успішне виконання команди.
* **`1`** — помилка (файл не знайдено, синтаксична помилка із вказанням рядка/колонки, використання неініціалізованої змінної або перевищення ліміту ітерацій циклу).

## Конформанс-тести (`run_tests.py`)

Для перевірки відповідності реалізації формальній специфікації БНФ SIPL використовується набір із 20 тестів (вимога **CORE-06**).

### Формат тестів
* **`tests/positive/`** (`test01.sipl` – `test10.sipl`): коректні програми мовою SIPL, що покривають присвоювання, арифметичні та булеві вирази, послідовну композицію, умовний оператор `if-then-else`, цикли `while-do`, блоки `begin-end` та порожній оператор `skip`. Очікується успішний парсинг та виконання без помилок.
* **`tests/negative/`** (`neg01.sipl` – `neg10.sipl`): програми з порушенням синтаксису або лексики (незакриті блоки `begin`, пропущені ключові слова `then`/`do`, некоректні токени). Очікується генерація синтаксичної діагностики парсером.

### Запуск тестів
```bash
python run_tests.py
```

## Візуалізація дерев розбору (`visualize.py`)

Модуль візуалізації генерує представлення дерева конкретного синтаксичного виводу (**Parse Tree**) та абстрактного синтаксичного дерева (**AST**) з прив'язкою до координат вихідного коду (вимоги **VIS-01**, **VIS-02**):

```bash
python visualize.py tests/positive/test04sipl
```

Після запуску в корені проєкту створюються 4 артефакти:
1. **`parse_tree.txt`** — форматоване текстове представлення Parse Tree.
2. **`parse_tree.json`** — JSON-структура Parse Tree з позиціями токенів (`line`, `col`).
3. **`parse_tree.dot`** — опис графа у форматі Graphviz DOT (придатний для рендерингу у SVG/PNG).
4. **`comparison.html`** — вебсторінка для візуального порівняння Parse Tree та AST поруч.

## Обмеження та особливості реалізації

* **Типи даних:** Підтримуються цілі числа (`int`) та логічні умови у конструкціях `if` і `while`. Ділення виконується як цілочисельне (`//`) з перевіркою ділення на нуль.
* **Захист від зациклення:** Інтерпретатор має вбудований ліміт кількості кроків виконання (за замовчуванням `10 000` ітерацій), при перевищенні якого виконання переривається з відповідним повідомленням про помилку.
* **Область видимості:** Усі змінні в програмі SIPL мають глобальну область видимості в межах поточного запуску; звернення до змінної до її ініціалізації викликає помилку часу виконання.
